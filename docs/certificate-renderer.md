# Certificate Renderer

Run `npm run serve`, open `http://127.0.0.1:8173/#/passport`, and select a
certificate's details. The image preview and PNG/PDF buttons appear below its
record details. Local demo credentials are explicitly preview-only. A profile
name, credential skill and valid issue date are required; missing fields show an
error rather than invented data. The renderer does not issue or verify records.

## Data and status

- Official historical records use only API `credential.snapshot`: recipientName,
  subject and issuedAt (mapped by backend from the immutable DB fields). Profile,
  top-level skill and the current clock never override these fields.
- Preview uses current Profile name and preview skill/date, with PREVIEW — NOT
  ISSUED stamped into exports. A missing date is not replaced with today's date.
- Issued is a historical state; Verified additionally requires the existing
  `hasActualAvalancheVerification` predicate. Official download buttons are
  available only with complete snapshot and valid evidence verification.
- Revoked/revoke-pending records retain historical fields, show a REVOKED stamp,
  and have no exports. Legacy/malformed/mismatched snapshots show
  `Chứng nhận thiếu dữ liệu lịch sử` without canvas or exports; no Profile fallback.
- Snapshot version and record ID/code binding are checked. Resolved display data
  is frozen, and no editing/override inputs or API writes are added. These are UI
  integrity controls, not protection against a user modifying their own browser.
- Avalanche binds evidence hash, not Name/Subject. PNG/PDF are not independently
  authenticated documents; the API record remains the source of metadata.

## Certificate ID

The API's `code` (DB `credential_code`) is passed to the renderer and cross-checked
against `snapshot.certificateCode`. It is displayed beside the preview and in
canvas accessibility metadata. No ID is generated by the frontend. The PNG has
no dedicated ID slot, so ID is not drawn into its design in this phase. Proposed
follow-up: an approved small footer line below the date/signature section, with
long-code fitting and visual review, rather than covering an existing ornament.

## Template

Original: `assets/certificates/certificate-template.png` (1536 × 1024).
Runtime: `assets/certificates/certificate-template-clean.png`.
Rebuild with `node scripts/clean-certificate-template.mjs`.

Placeholders are baked into the original PNG. The script replaces only their
three interior regions with adjacent matching paper texture and blends the
edges. This reconstructs the obscured background; it cannot recover original
pixels hidden by text. No white rectangles are used. Every decoded pixel
outside the repair regions remains identical, including gold frames, logo and
medal. The original remains intact.

Text centers after visual review: NAME (768,500), SUBJECT (768,649), DATE
(441,892). Self-hosted Be Vietnam Pro supports Vietnamese. Text shrinks to fit
the available width, with a 14px minimum; excessively long values are rejected
rather than clipped or rendered unreadably.

PNG exports at native resolution. PDF is a single A4 landscape page containing
a high-quality raster of the certificate, centered without stretching. Text is
not selectable in the PDF. No external library, CDN or new API is needed.

## Verification

`npx playwright test tests/certificate-renderer.spec.js` covers data/date/state,
pixel-preserving cleanup, short/long/Vietnamese text, PNG/PDF dimensions and
structure, and downloads through the actual Passport modal. Visual previews
are saved under `test-results/`. All evidence in these tests is local/mock;
they do not perform Avalanche transactions or prove deployed issuance.
