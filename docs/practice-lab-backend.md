# Practice Lab backendThe Practice Lab now has a real, server-scored backend. The browser neverreceives an answer key before submitting an attempt, and progress is derivedfrom stored attempts rather than from `localStorage`.## Routes| Method | Route | Purpose || --- | --- | --- || `GET` | `/api/practice?lang=vi\|en\|jp` | Localized challenge list and the signed-in learner's progress. No answer keys. || `POST` | `/api/practice` | `{ action: "submitAttempt", challengeSlug, selectedOption, clientAttemptId, lang }`. Scores on the server and returns the explanation with the new progress. |The frontend client is `practice-service.js`; runtime state and rendering live in`practice-actions.js` and `views/practice.js`.Vercel Hobby allows 12 serverless functions. `/api/practice` is therefore arewrite to `/api/learning-records?practice=1` in `vercel.json`, and thelearning-records function delegates to `api/practice/_handler.js`. Helpermodules inside `api/practice/` start with `_`, so Vercel does not count them asfunctions. The local static server still exposes `/api/practice` directly.## Data modelMigration: `supabase/migrations/202611090001_practice_lab.sql`Rollback: `supabase/rollback/202611090001_practice_lab.sql`- `practice_challenges`: server-owned definitions, including `correct_option`  and multilingual `content` (`vi`, `en`, `jp`).- `practice_attempts`: one row per submitted attempt, owned by `learner_id`.  `unique (learner_id, client_attempt_id)` makes retries idempotent.- `practice_progress`: read-only aggregate view for SQL reporting. It never  exposes answers or selected options.The migration is additive and does not alter existing learning-record,credential, achievement, or auth tables.## Security and correctness- Answer keys stay on the server. `GET` returns only public challenge fields.- The server computes `is_correct`; the client's claim is ignored.- Every attempt is scoped to the authenticated learner. Learner A cannot read  or deduplicate against learner B's attempts, even with the same client id.- Reusing a `clientAttemptId` for another challenge returns  `409 PRACTICE_ATTEMPT_CONFLICT` instead of leaking that challenge's answer.- Input validation rejects unknown actions, malformed slugs, non-integer or  out-of-range options, and non-UUID attempt ids before any write.- RLS is enabled on both tables with no policies for `anon`/`authenticated`.  Only the service role used by the API can read or write. The API adds the  learner filter itself.- Supabase learners use `auth.users.id`; Local Auth learners use the stable  `local:<email>` id so progress survives a new Local Auth session id.## Local developmentWhen Local Auth is active (`LOCAL_AUTH_ENABLED=1` and the client has the`paradox-local-server` marker), the API uses a server-side SQLite database at`.data/practice-local.sqlite` (or `PRACTICE_LOCAL_DB_PATH`). `node:sqlite` isloaded only for Local Auth requests; production requests use the Supabase RESTstore. `.data/` is ignored by git.Demo challenges remain in `demo.js`. If the backend is disabled, the page keepsthe labelled demo flow and its existing `localStorage` progress. Demo mode isnever presented as real data.## Safe migration from demo progress (proposal only, not automatic)Existing keys are deliberately left untouched:- `paradox-user:<email>:practice`- `paradox-user:<email>:practice-activity`Recommended later migration, only with explicit user action:1. Read the numeric demo indexes from `practice`.2. Map index `0..5` to the stable slugs in `api/practice/_challenges.js`.3. Submit each mapped slug once, with a generated `clientAttemptId`, and mark   it as a demo import (for example a future `imported_from` column) so imported   attempts can be distinguished from real attempts.4. Keep the old keys until the import is confirmed; then remove them in a   separate, reversible step.This is not implemented automatically because demo answers are not evidence ofreal learning.## VerificationRun:```powershellnpx playwright test tests/practice.spec.js tests/vercel-deployment.spec.js tests/app.spec.js tests/real-data-ui.spec.js tests/local-auth.spec.jsnpx playwright test```Last local run:- `tests/practice.spec.js`: 8 passed.
